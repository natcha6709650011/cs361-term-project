# cs361-term-project
# Room Reservation & Utilization Management System

## Project Vision

สร้างระบบกลางที่ช่วยให้ผู้ใช้งานสามารถเข้าถึงข้อมูลห้องได้อย่างสะดวกและเป็นระบบ โดยมีข้อมูลเกี่ยวกับประเภทห้อง ความจุ อุปกรณ์ สิ่งอำนวยความสะดวก เงื่อนไขการใช้งาน และกติกาการจอง เพื่อเป็นพื้นฐานสำหรับการพัฒนาระบบค้นหา จอง อนุมัติ และติดตามการใช้ห้องใน Version ถัดไป

---

# V1 – Information

## Objective

V1 มุ่งเน้นการให้ผู้ใช้สามารถเข้าถึงข้อมูลพื้นฐานของห้องได้ โดยยังไม่จำเป็นต้องเข้าสู่ระบบ

## In Scope

ผู้ใช้สามารถดูข้อมูลพื้นฐานของห้อง เช่น

- ประเภทห้อง
- ความจุ
- อุปกรณ์
- สิ่งอำนวยความสะดวก
- เงื่อนไขการใช้งาน
- กติกาการจอง

## Out of Scope for V1

ฟังก์ชันต่อไปนี้ยังไม่อยู่ใน V1:

- การเข้าสู่ระบบและ Authentication
- การสร้าง แก้ไข หรือยกเลิกการจอง
- การอนุมัติการจอง
- การจัดการข้อมูลห้องโดย Admin
- การบันทึก Check-in / No-show
- การบันทึก Actual Usage
- การวิเคราะห์ Utilization
- Dashboard สำหรับผู้ดูแลหรือผู้บริหาร

ฟังก์ชันเหล่านี้จะพัฒนาตาม Requirements ของ V2–V7

---

## Assumptions / To Validate

- ข้อมูลห้องในปัจจุบันมาจากไหน?
- ข้อมูลห้องที่มีอยู่สามารถนำมาใช้ในรูปแบบ Spreadsheet, Database หรือ API ได้ไหม?
- ข้อมูลห้องและข้อมูลการจองมีการอัปเดตบ่อยแค่ไหน?
- V1 จำเป็นต้องแสดงสถานะห้องว่างแบบ Real-time หรือไม่?

---

## Data Ownership / Source of Truth

- ระบบ V1 จะเน้นการ **นำข้อมูลห้องที่มีอยู่เดิมมาแสดง** มากกว่าการสร้างข้อมูลใหม่ผ่านระบบ
- ระบบควรเชื่อมต่อหรือรับข้อมูลจาก **แหล่งข้อมูลเดิม** หากสามารถทำได้
- ผู้ดูแลและแหล่งข้อมูลหลัก (**Source of Truth**) ยังต้อง Validate

ระบบ V1 รับผิดชอบการ:

- แสดงอุปกรณ์และสิ่งอำนวยความสะดวก
- แสดงเงื่อนไขการใช้งาน
- แสดงกติกาการจอง

## Outside the System – V1

สิ่งที่ยังอยู่นอกขอบเขตของ V1 ได้แก่:

- Authentication / Login
- การสร้างและจัดการการจอง
- การอนุมัติการจอง
- การจัดการข้อมูลห้องโดยผู้ดูแล

- Dashboard และสถิติการใช้ห้อง
- การสร้างหรือแก้ไขข้อมูลในแหล่งข้อมูลต้นทาง

## External Actors

สำหรับ V1 มี External Actor หลักคือ:

- **ผู้ใช้ทั่วไป** — เข้าถึงและดูข้อมูลพื้นฐานของห้องโดยไม่จำเป็นต้องเข้าสู่ระบบ

บทบาทอื่น เช่น นักศึกษา อาจารย์ เจ้าหน้าที่ และผู้ดูแลระบบ จะเข้ามามีบทบาทใน Version ถัดไป เมื่อระบบรองรับ Authentication, Reservation และ Management

## External Systems / Data Sources

ระบบอาจรับข้อมูลห้องจากแหล่งข้อมูลที่มีอยู่เดิม เช่น:

- Database
- API
- หรือแหล่งข้อมูลอื่นของสาขาวิชา

รูปแบบและแหล่งข้อมูลหลักที่แน่นอนยังต้อง Validate

# V2 – Room Availability Search

## Objective

V2 มุ่งเน้นการเพิ่มความสามารถในการค้นหาห้องที่ว่างตามเงื่อนไขที่ผู้ใช้ต้องการ โดยต่อยอดจาก V1 ที่สามารถแสดงข้อมูลและรายละเอียดของห้องได้

ผู้ใช้สามารถระบุวันที่ เวลา ความจุ และประเภทห้อง เพื่อค้นหาห้องที่ตรงตามเงื่อนไขและไม่มีการใช้งานซ้อนในช่วงเวลาที่เลือก


## In Scope

ผู้ใช้สามารถ:

- เลือกวันที่ต้องการใช้ห้อง
- ระบุเวลาเริ่มต้น
- ระบุเวลาสิ้นสุด
- ระบุจำนวนผู้ใช้งานหรือความจุที่ต้องการ
- เลือกประเภทห้อง
- ค้นหาห้องตามเงื่อนไขที่ระบุ
- ดูรายการห้องที่ตรงตามเงื่อนไข
- ตรวจสอบว่าห้องว่างในช่วงเวลาที่เลือกหรือไม่
- เลือกห้องจากผลการค้นหาเพื่อดูรายละเอียดของห้อง

ระบบจะใช้ข้อมูลตารางการใช้งานห้องเพื่อช่วยตรวจสอบว่าห้องมีการใช้งานในช่วงเวลาที่ผู้ใช้เลือกหรือไม่


## Out of Scope for V2

ฟังก์ชันต่อไปนี้ยังไม่อยู่ใน V2:

- การเข้าสู่ระบบและ Authentication
- User Account
- การสร้างรายการจอง
- การแก้ไขรายการจอง
- การยกเลิกรายการจอง
- การอนุมัติการจอง
- การจัดการข้อมูลห้องโดย Admin
- การบันทึก Check-in / Check-out
- การบันทึก No-show
- การบันทึก Actual Usage
- การวิเคราะห์ Utilization
- Dashboard สำหรับผู้ดูแลหรือผู้บริหาร
- Notification

ฟังก์ชันเหล่านี้จะพัฒนาตาม Requirements ของ Version ถัดไป

---

## Assumptions / To Validate

- ข้อมูลตารางการใช้ห้องสามารถจัดเก็บใน Database ได้
- ข้อมูลตารางการใช้ห้องมีข้อมูลวันที่และช่วงเวลาการใช้งาน
- ข้อมูล Room Schedule สามารถเชื่อมโยงกับข้อมูลห้องที่มีอยู่ใน V1 ได้
- กฎในการตรวจสอบช่วงเวลาที่ทับซ้อนกันสามารถกำหนดได้อย่างชัดเจน
- สถานะห้องว่างใน V2 เป็นการคำนวณจากข้อมูล Schedule ที่มีอยู่ในระบบ
- V2 ยังไม่สร้างรายการจองจริงจากการค้นหาห้อง


## Data Ownership / Source of Truth

- V2 ยังคงใช้ข้อมูลห้องจาก Database ของ V1
- ข้อมูลประเภทห้องและข้อมูลห้องยังคงใช้จากตาราง `room_types` และ `rooms`
- V2 เพิ่มข้อมูลตารางการใช้ห้องใน `room_schedules`
- `room_schedules` ใช้เป็นข้อมูลสำหรับตรวจสอบว่าห้องมีการใช้งานในช่วงเวลาที่ผู้ใช้ค้นหาหรือไม่
- ระบบ V2 ใช้ Database เป็นแหล่งข้อมูลหลักสำหรับการค้นหาห้องว่าง
